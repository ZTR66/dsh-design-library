# 视频制作 · 约束与标准调用链

给 AI 用的工作规程。**不规定选什么，只规定怎么选、按什么顺序、什么算做完。**

---

## 一、为什么需要这份规程

从三次真实会话里看出来的行为模式：

| 现象 | 证据 |
|---|---|
| 先摸环境，后想内容 | 前 10 次调用全是环境探查，没想过「这片子讲什么」 |
| 设计库几乎空白 | 一条会话 109 次调用里，设计库只占 6 次 |
| 风格自己发明 | 写了 `Signal Red / Terminal Brutalist`，没读过 44 个风格 |
| 读了 2 张卡就写 12 个分镜 | 124 张卡里用了 2 张 |
| 陷入读图自检循环 | 反复渲染、怀疑、改，耗时远超实际产出 |

**这份规程针对的就是这五条。**

---

## 二、硬约束（可检查，不靠自觉）

### C0 · 开工前必须确认用户的干预意图

**在调用任何工具之前，先问一句。**

这不是客套，是流程分叉点：用户的答案决定后面三个关键决策（风格、结构、镜头）是他过目还是直接放行。

#### 怎么问

一次问清，不要分几次：

> 这支片子我可以全权处理，还是你想在每个关键节点确认一下？
>
> 全权处理：我直接定风格、结构、镜头，做完给你看成品。
> 逐步确认：风格选好了先给你看，结构定了再给你看，镜头配好了再给你看。

#### 三种回答，三条路

| 用户回答 | 模式 | 后续行为 |
|---|---|---|
| 「你决定」「随便」「快点」 | **自主** | 三个决策点不打断，一次交付 |
| 「给我看」「先确认」 | **确认** | 三个决策点各停一次 |
| 没回答 / 含糊 | **默认确认** | 按确认模式走 |

**默认确认，不是默认自主。** 做错了返工成本比多问一次高。

##### 「用户看起来很急」不是不问的理由

这是被真实会话验证过的漏洞：一条会话的模型在思考里写道

> 「『！！！』说明他们就想要这个东西。嗯，但我有 ask_user_question 可用，问一句……」

**它想到了要问，然后用「用户很急」说服自己不问了。**

这个判断是错的，因为：

- **急的是拿到成品，不是省掉这 30 秒。** 选错风格要重做整片，那才是真的浪费时间。
- **感叹号、催促、语气都不是答案。** 只有用户说了「你决定」「随便」才算自主。
- **问一次的成本是 30 秒，猜错的成本是几小时。** 这个账在任何语气下都成立。

**只有两种情况可以不问：**

1. 用户在**同一句话里**明确说过「你决定 / 随便 / 快点定 / 不用问」；
2. 用户在**本次会话更早**已经明确交代过工作方式。

其他一切情况——包括「用户看起来很急」「需求已经很明确」「我自己能判断」——**都要问**。

**违反判定**：模型思考里出现「用户可能不想被打扰」「看起来他们就要结果」之类的推理，然后跳过了询问。

#### 确认模式下，在哪三个点停

不是每一步都问，只在**改了代价最高**的三个节点停：

```
节点 1 · 风格定了
  ↓ 展示：决策卡（色板、字体、候选对比、理由）
  ↓ 问：「这个方向对吗？要不要换？」
  ↓ 用户确认后 → 继续

节点 2 · 结构定了
  ↓ 展示：分镜表（段落、时长、悬念位、反转位）
  ↓ 问：「这个节奏对吗？有没有要加的段落？」
  ↓ 用户确认后 → 继续

节点 3 · 镜头配好了
  ↓ 展示：每段用什么卡、什么参数（表格）
  ↓ 问：「这样拍可以吗？」
  ↓ 用户确认后 → 写代码
```

**写代码之后不再打断**，直到成品。

#### 为什么要问

三次真实会话里，AI 直接开工，做完才发现方向不对。返工的代价：

```
风格选错 → 所有色板/字体/材质要重做
结构错了 → 分镜全部重排
镜头错了 → 每段的动画要重写
```

**在节点上花 30 秒确认，省的是几小时的返工。**

#### 违反判定

- 没问就直接开工
- 问了但没按回答执行（用户说要确认，结果直接交付）
- 确认模式下跳过了任何一个节点

### C1 · 第一个工具调用必须是 `video_guide`

不带参数，看全库：44 风格 · 124 镜头卡 · 8 家族 · 10 类别。

**违反判定**：在 `video_guide` 之前调用了任何渲染、探测、写文件类工具。

> 允许在它之前**读用户给的文件**（比如剧本、参考图），但不允许调工具探查环境或写代码。

---

### C2 · 环境检查排在规格之后

任何环境检查类工具（`video_env_check`，或其它插件提供的同类工具）只能在**分镜规格写完之后**调用。

> 这一段只说顺序，不指定用哪个环境工具——那些工具可能来自别的插件，装不装由用户决定。
> 有就查，没有就跳过，不影响本规程的其余部分。

**理由**：环境只决定「怎么实现」，不决定「做什么」。先查环境会让 AI 顺着工具限制倒推内容。

**违反判定**：两个 `*_env_check` 出现在分镜表之前。

---

### C3 · 风格必须经过程序，不能自己发明

必须走完这三步：

```
video_guide({ topic: '<你的题材>' })      → 拿到候选
video_style_read({ key }) × 2             → 至少读 2 个
选定一个，写出理由
```

**必须产出的决策卡**：

```
风格：<key> <中文名>
底色：<hex>
主色：<hex> ×2
字体：<字体名>
候选对比：A 适合X但Y / B 适合Y但X / 选 A 因为…
```

**违反判定**：
- 代码里出现色板，但这个色板不在 `video_style_read` 的返回里
- 只读 1 个风格就定了
- 没有候选对比

---

### C4 · 如果选暗底，必须解释为什么不用亮底

库里有一批亮底风格，都可以考虑：

```
chalk      粉笔黑板     paper     水墨纸本
editorial  杂志编辑     poster    国家公园海报
riso       孔版印刷     journal   手账涂鸦
variety    综艺花字     memphis   孟菲斯波普
```

**「科技感」「高级感」不是理由** —— 那是套话，任何风格都能这么说。

**有效理由的样子**：
> 选了 `neon` 而不是 `editorial`，因为这支片子要表现「故障/中断」，霓虹的扫描线和断电闪烁是内容的一部分，而杂志编辑的静态排版传达不了这个。

**违反判定**：出现暗底色板（亮度 < 40%）但没有这段说明。

---

### C5 · 结构必须来自 `structure-bible`

调 `video_craft_read({ id: 'structure-bible' })`，按它给的四种骨架之一分配时长。

```
A 历史接力      B 反常现象+模型
C 隐喻+重新解读  D 短谜题（60-90s）
```

**必须说明**：选了哪个骨架、为什么、悬念埋在第几秒、反转在第几秒。

**违反判定**：分镜表有段落划分，但没有对应到四种骨架之一。

---

### C6 · 每段必须有镜头卡，且读过完整参数

```
每段 1-2 张卡
每张卡调过 video_shot_read({ name })
```

**分镜表里每段必须有一行**：

```
| 时间 | 内容 | 卡名 | 关键参数 |
| 0-3s | 钩子 | crash-zoom-punch | zoom 6f 1→2.6, 震屏 amp14 τ1.8 |
```

**违反判定**：
- 某段没有卡名
- 有卡名但没调过 `video_shot_read`

---

### C7 · 缓动曲线必须能追溯

代码里每个 `cubic-bezier` / 缓动函数，必须对应到 `animation-principles` 里的具体数值：

```
入场  cubic-bezier(0.16, 1, 0.3, 1)      300-500ms
退场  cubic-bezier(0.7, 0, 0.84, 0)      200-300ms
位移  cubic-bezier(0.65, 0, 0.35, 1)     300-400ms
弹跳  cubic-bezier(0.34, 1.56, 0.64, 1)  400-600ms
```

**违反判定**：出现 `ease-in-out 0.3s` 这类凭感觉写的值，且没有文档出处。

---

### C8 · 分段渲染，逐段验收

**不要一次渲染整片。**

这条针对的是三次真实会话里最耗时的部分：整片渲染 → 读图 → 发现了问题 → 改一个参数 → 又整片重渲。**每次都全片重来，一次几分钟到几十分钟。**

#### 渲染单元是「段」，不是「片」

一段 = 一个镜头 = 一个独立文件。

```
片长 40 秒，6 个段落
  → 渲染 6 个独立文件：seg-01.mp4 … seg-06.mp4
  → 全部通过后，一次性拼接
```

**不要**：写一个渲染全片的脚本，跑一次等十分钟。

**应该**：写一个渲染单段的脚本，跑 6 次，每次几十秒。

#### 每段渲染完立刻验收

```
渲染 seg-03.mp4
  ↓
检查：
  · ffprobe 时长对不对（脚本算出来的预期 vs 实际）
  · 帧数对不对
  · 文件大小在合理范围
  · 抽 2 帧看关键画面
  ↓
通过 → 下一段
不通过 → 只重渲这一段
```

**验收通过的是单段，不是整片。**

#### 为什么抽 2 帧而不是更多

一段只有 3-8 秒，抽**首帧和末帧**就够了：

- 首帧验证「入场状态对不对」
- 末帧验证「落位状态对不对」

中间的过渡交给参数保证（帧数、缓动都是设计库里查来的，不是估的）。

**抽太多帧反而会陷入自我怀疑**——三次会话里 AI 就是这样反复看、反复改，产出反而更差。

#### 拼接是纯机械操作

6 个段都通过后：

```
ffmpeg concat demuxer（无损，几秒完成）
+ 音频轨
→ 成品
```

**拼接不应该失败。** 如果失败了，说明段的编码参数不一致（分辨率、帧率、像素格式），这是脚本的 bug，不是内容问题。

#### 重渲的代价

| 做法 | 改一个参数要重渲多久 |
|---|---|
| 整片一次渲染 | 全部时长（几分钟到几十分钟） |
| **分段渲染** | **只有那一段（几秒到几十秒）** |

**这是分段渲染的全部意义。**

#### 违反判定

- 写了一个直接产出整片 MP4 的脚本，中间没有单段文件
- 分段渲染了，但没有逐段检查就拼接
- 某段发现问题后，重渲了整片而不是只重渲那一段

### C9 · 交付必须附 `decisions.md`

```markdown
# 决策记录

## 风格
选定：aurora / #070B1E
候选：aurora（选）、neon（否：霓虹强调故障，本片不需要）
理由：…

## 结构

悬念：第 12 秒抛出，第 32 秒解开

## 镜头
| 时间段 | 卡名 | 参数来源 |
|---|---|---|

| …    | …                | … |

每个曲线的出处：animation-principles 的「Timing」表
```

**违反判定**：没有 `decisions.md`，或内容与代码不符。

## 三、标准调用链

### 阶段 0 · 确认意图（0 次工具调用）

**这是第一个动作，不是第一个工具调用。**

先问用户：全权处理，还是每个节点确认？（见 C0）

用户的答案决定后面三个阶段是否停下来。

**这一步不调工具。** 答案拿到之前不要开始。

---

### 阶段 1 · 读题（0 次工具调用）

先在心里回答三个问题：

1. 这支片子让观众**记住哪一件事**？
2. 观众看完应该**做什么**？
3. 时长和平台是什么？

**这一步不调工具。** 想不清楚就不要往下走。

---

### 阶段 2 · 看库（1 次调用）

```
video_guide()
```

读返回的 11336 字符，找到：

- 你的题材落在哪个题材组
- 那个组有哪些风格
- 十个镜头类别各有多少张

---

### 阶段 3 · 定风格（3-4 次调用）

```
video_guide({ topic: '<题材>' })          ① 收窄候选
video_style_read({ key: 'A' })            ② 读候选 A
video_style_read({ key: 'B' })            ③ 读候选 B
→ 写决策卡（C3），选定
```

**产出**：风格决策卡（色板、字体、理由、候选对比）

**确认模式下 → 停下来给用户看（节点 1）**

---

### 阶段 4 · 定结构（1 次调用）

```
video_craft_read({ id: 'structure-bible' })
```

按它给的 130 秒基准等比压缩到你的时长。

**产出**：段落划分 + 每段时长 + 悬念/反转位置

**确认模式下 → 停下来给用户看（节点 2）**

---

### 阶段 5 · 配镜头（2-6 次调用）

按每段需要的能力搜：

```
video_shot_search({ category: '<category>' })   按需
video_shot_read({ name })                       每段 1-2 张
```

**十个类别**：

```
opening(11)  typography(22)  ui-entrance(21)  camera(10)
data(5)      interaction(11) transition(15)   rhythm(8)
effects(15)  outro(6)
```

**产出**：分镜表（C6 的表格）

**确认模式下 → 停下来给用户看（节点 3）**

---

### 阶段 6 · 取动效参数（1 次调用）

```
video_craft_read({ id: 'animation-principles' })
```

**产出**：缓动/时长对照表（C7）

---

### 阶段 7 · 查环境（2 次调用）

**现在才查。**

```
video_env_check()      渲染能力（本插件自带）
其它环境工具            音频/语音等能力，装了才用
```

> 只查你实际会用到的部分。没有音频需求就不用查音频能力。

**产出**：确认能做什么，缺什么（缺的装或换方案）

---

### 阶段 8 · 写代码（0 次设计库调用）

现在参数齐了，写渲染脚本。

**关键**：

- 用阶段 3 的色板，不要自己调色
- 用阶段 5 的帧数和曲线，不要自己估
- 用阶段 6 的缓动，不要写 `ease-in-out`

**确认模式下不再打断**，直到成品。

---

### 阶段 9 · 分段渲染与逐段验收

**渲染单元是段，不是片。**

```
for 每一段 in 分镜:
    渲染 seg-NN.mp4           只渲这一段，几十秒
    ffprobe 校验              时长/帧率/分辨率对不对
    抽首末 2 帧看              入场对不对、落位对不对
    通过 → 记下来
    不通过 → 改参数，只重渲这一段
```

**每段通过后再进下一段**，不要等所有段都渲完才检查。

**产出**：`seg-01.mp4` … `seg-06.mp4`，每个都验过。

---

### 阶段 10 · 拼接与交付

**这一段是纯机械操作，不应该有创意决策。**

```
ffmpeg concat（无损，几秒）
+ 音频轨（如果有配音）
→ 成品 MP4
```

**拼接前确认**：所有段的分辨率、帧率、像素格式一致。不一致是脚本 bug，不是内容问题。

**最终校验**（数值，不是看图）：

```
ffprobe：总时长 = 各段时长之和？
        分辨率 / 帧率符合预期？
文件大小合理？
```

**交付**：视频 + `decisions.md`

## 四、调用次数预算

| 阶段 | 调用数 | 累计 |
|---|---|---|
| 0 确认意图 | 0（问一句话） | 0 |
| 1 读题 | 0 | 0 |
| 2 看库 | 1 | 1 |
| 3 定风格 | 3-4 | 4-5 |
| 4 定结构 | 1 | 5-6 |
| 5 配镜头 | 2-6 | 7-12 |
| 6 取动效 | 1 | 8-13 |
| 7 查环境 | 2 | 10-15 |
| 8 写代码 | 0 | 10-15 |
| 9 分段渲染+验收 | 1-2（每段 1 次校验） | 11-17 |
| 10 拼接 | 0 | 11-17 |

**设计库调用应该占 6-9 次。**

对比实际会话：只有 1 次（还是环境检查）。

## 五、自检清单

交付前逐条对照：

- [ ] **开工前问过用户「全权处理还是逐步确认」**
- [ ] **确认模式下，在风格/结构/镜头三个节点各停了一次**
- [ ] 第一个工具调用是 `video_guide`
- [ ] `*_env_check` 在分镜表之后
- [ ] 读了至少 2 个风格并写出对比
- [ ] 暗底风格有说明
- [ ] 结构对应到 `structure-bible` 的四种骨架之一
- [ ] 每段都有卡名，且都读过 `video_shot_read`
- [ ] 每个缓动能追溯到 `animation-principles`
- [ ] 渲染产出的是多个单段文件，不是一次性整片
- [ ] 每段渲染完立刻验收（ffprobe + 首末 2 帧）
- [ ] 发现问题只重渲那一段，没有全片重来
- [ ] 拼接前确认所有段参数一致
- [ ] 有 `decisions.md`
- [ ] 设计库调用 ≥ 6 次

**任何一条不满足，说明没按规程走。**

## 六、规程不规定的事

留给你判断的：

| 项 | 为什么留给 AI |
|---|---|
| 选哪个风格 | 题材匹配有多个合理答案 |
| 骨架选哪个 | A/B/C/D 都可能是对的，取决于内容 |
| 每段用哪张卡 | 同样的段落目标有不同的表达方式 |
| 节奏快慢 | 取决于题材和平台 |
| 用什么技术栈 | Canvas / Remotion / ffmpeg 都行 |

**规程只管「必须看过、必须能追溯、不能瞎编」。**
